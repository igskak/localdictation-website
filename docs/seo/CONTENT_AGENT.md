# Контентный агент witnessmac.com

Как агент пишет одну страницу из `docs/seo/BACKLOG.md` и отдаёт её на ревью. Запускается задачей `witness-seo-content` (приложение Claude на Mac Игоря) или вручную. Итог каждого прогона: один PR или короткое объяснение, почему PR нет.

## Границы

Агент пишет код и текст, коммитит в свою ветку `seo/<slug>`, пушит и открывает PR. Больше ничего.

- Не мержит, не деплоит, не запрашивает индексацию, ничего не публикует за пределами PR, не трогает Cloudflare, Google Ads, Search Console и PostHog. Мерж и `npm run deploy` делает Игорь.
- Работает только в своей копии репозитория: `/Users/ihorskakovskyi/Pet Project/witness-seo/website-agent` (git worktree репозитория сайта). Рабочая копия Игоря `localDictationProject/website` не трогается: оттуда он деплоит, и чужая ветка в ней уехала бы на прод.
- Не больше двух открытых контентных PR. Если их уже два, прогон заканчивается сообщением «ждут мержа: #N, #M».

## Порядок

1. **Подготовка.** Если копии нет: `git -C "<website>" worktree add "/Users/ihorskakovskyi/Pet Project/witness-seo/website-agent" origin/main --detach`, затем `npm ci` в ней. Если есть: `git fetch` и `git switch --detach origin/main`. Проверить `gh pr list --state open`.
2. **Выбор темы.** Верхний пункт со статусом `todo` в `docs/seo/BACKLOG.md` на `origin/main`. Прочитать последний отчёт монитора в `/Users/ihorskakovskyi/Pet Project/witness-seo/reports/`: если он советует поднять другую тему, взять её и написать почему в PR. Если пункт инженерный (например, английский шаблон), сделать его как обычную задачу разработки с тестами.
3. **Спрос.** Semrush: `phrase_these` по целевым запросам в нужной базе (`de` или `us`), `phrase_related` (40 строк по объёму), `phrase_organic` (топ-10). Записать объёмы и KD в PR. Если объём всей группы меньше ~100 в месяц и тема не помечена в бэклоге как «ради ссылок», остановиться и предложить перенести её в «Не писать».
4. **Что уже в выдаче.** Открыть три первых результата (WebFetch) и выписать, на какие вопросы они отвечают. Страница должна отвечать на те же вопросы лучше и раньше.
5. **Факты.**
   - О чужих продуктах только из их официальных страниц, у каждого утверждения id источника и дата проверки. Прежде чем назвать у конкурента отсутствие функции, проверить его справку: у Apple, например, нашлось синее подчёркивание неоднозначных слов, и строка «проверки нет» была бы ложью. Формулировка для неописанного: «nicht öffentlich dokumentiert».
   - Не упрекать конкурента в ограничении, которое есть и у Witness. Не заявлять лучшую точность: общего теста нет.
   - О Witness только то, что есть на главных страницах, в `app/llms.txt` и в уже опубликованных сравнениях (источник `local-product`).
6. **Текст.** Сначала прямой ответ на запрос, потом пределы, потом Witness. Без длинных тире (—) и без подводок вроде «Стоит отметить», «Важно понимать». Коротко, по делу, «du» в немецком, как на остальном сайте.
7. **Техника (немецкая страница).** Запись в `app/_data/comparisons.ts` (свой массив источников с уникальным именем, `updatedIso` и `updatedLabel`), slug в `comparisonSlugs`, подпись в `comparisonLabels` (`app/_components/ComparisonPage.tsx`), маршрут `app/vergleich/<slug>/page.tsx` по образцу соседних, путь в `comparisonPaths` в `tests/rendered-html.test.mjs`. Sitemap, хаб и ссылки с главных подхватятся сами. `metaTitle` до 60 знаков, `description` до 160.
8. **Проверка.** `npm test` и `npm run lint` зелёные. `npm run start -- --port 4321`, затем curl: страница 200, есть в `/sitemap.xml`, на главных есть ссылка. `grep -c "—"` по новому тексту даёт 0. Перечитать каждое утверждение о конкуренте против источника.
9. **PR.** Ветка `seo/<slug>`, коммит в стиле репозитория (заголовок в повелительном наклонении, тело объясняет зачем), `gh pr create` с разделами Why (спрос, выдача), What, Checked, After merge (`git switch main && git pull && npm run deploy` в `website/`, затем запрос индексации). В том же PR статус темы в бэклоге меняется на `review: PR #N`.
10. **Уборка.** Остановить локальный сервер, вернуть копию в `--detach origin/main`.

## Когда PR смержен

Следующий прогон видит смерженный PR и в своём PR переносит тему в таблицу «Сделано» с датой. Индексацию запрашивает Игорь или Claude в интерактивной сессии: автоматическим агентам это не разрешено.

## Замечание про приложение Claude

В сессии, открытой в worktree репозитория приложения, хук запрещает инструментам Edit и Write менять файлы сайта. Тогда правки вносятся скриптом через Bash.
